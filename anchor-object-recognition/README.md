# Anchor-based Object Recognition and Localization

**Computer Vision and Image Processing (R7020E), Luleå University of Technology** · group project (Group 6)

Given three anchor photos of one fire extinguisher, decide for every video frame whether that extinguisher is present and
draw a box around it, without accepting the printed pictures of extinguishers. Everything runs on a CPU; nothing is trained.

Three methods are compared, each without and with a depth-based cue penalty, plus a seventh system that keeps the
cues and has no matcher at all (seven systems): a colour-histogram baseline, SIFT, and a frozen DINOv2 embedding.
**Final system:** DINOv2 with the cue penalty.

## Results (thresholds tuned on `test`, reported on `eval`)

| System | eval P / R | test P / R |
|---|---|---|
| HSV histogram (baseline) | 1.00 / 0.98 | 0.84 / 1.00 |
| HSV + cues | 1.00 / 0.96 | 0.92 / 1.00 |
| SIFT | 0.66 / 0.66 | 0.49 / 0.83 |
| SIFT + cues | 0.97 / 0.93 | 0.95 / 0.96 |
| DINOv2 | 1.00 / 0.99 | 0.88 / 0.96 |
| **DINOv2 + cues (final)** | **1.00 / 1.00** | **0.95 / 1.00** |
| candidates + cues, no matcher | 1.00 / 0.95 | 0.95 / 0.96 |

`eval` contains no frame without the target, so it cannot test decoy rejection; that is only measured on `test`
(the tuning sequence). Candidates and depth cues already give strong results. DINOv2 with a soft cue penalty recovers two target frames
on `test` and six on `eval` that the no-matcher system rejects after a failed depth check. In all eight frames,
the no-matcher system selects a correct region before rejecting it. This comparison does not isolate box ranking alone.
Full tables are in `results/results_table.csv`, the slides and the report.

## Setup

1. Python 3.14 (other 3.10+ versions should work). Install the packages; the CPU build of PyTorch is enough:
   ```
   pip install torch==2.10.0 torchvision==0.25.0 --index-url https://download.pytorch.org/whl/cpu
   pip install -r requirements.txt
   ```
2. The course data is not included. Put the two folders from the course data (the `Project_3` recordings and the
   `Anchor_Images` photos) next to this folder, or edit the two paths in `configs/default.yaml`:
   ```
   Project_3/raw/test/camera_color_image_raw/*.png   (and camera_depth_image_raw/, same for eval)
   Anchor_Images_extracted/Anchor_Images/Anchor1.png, Anchor2.png, Anchor3.png
   ```
3. The first DINOv2 run downloads the `dinov2_vits14` weights (about 85 MB) from the official repository.

## Reproduce the results

Run from this folder.

```
python src/pipeline.py              # score every candidate with all matchers -> data/scores_*.csv
                                    #   (about a minute on a CPU; the first run also downloads the 85 MB DINOv2 weights)
python src/evaluate.py              # tune on test, report on eval -> results/results_table.csv, precision-recall curve
python src/evaluate.py analysis     # anchor, target-size and coverage analysis -> results/analysis.json
python src/visualize.py             # figures in results/figures and report/figures (after evaluate.py)
python src/make_tables.py           # LaTeX tables of the report from results_table.csv and analysis.json
python src/make_demos.py            # both titled H.264 demo videos (requires ffmpeg on PATH)
python src/verify_results.py        # independently check saved metrics; no raw images or model needed
```

The labels (`data/labels_test.json`, `data/labels_eval.json`) are included, so labelling is optional. To label again:
`python src/label_tool.py prelabel`, then `python src/label_tool.py` and open http://localhost:8000
(Enter = accept, N = target absent, drag = draw a box around the red body, U = next unreviewed frame).

| `evaluate.py` | depth cues, decision rule, threshold choice on the development sequence, metrics (TP, FP, FN, precision, recall, localization success), the seven systems, extra analysis |

| `label_tool.py` | first-guess boxes and the browser labelling tool |

## Metric definitions

A box is correct if its centre lies inside the reference box. TP: target present and a correct box accepted. FP: any accepted box that
is not a TP (a print, another object, or a misplaced box). FN: target present but not correctly found.
precision = TP / (TP + FP), recall = TP / frames with target, localization success = TP / all accepted detections.
Every accepted print or misplaced box fails localization, including accepts on target-absent frames. With one box
per frame and this correctness rule, localization success equals precision; report tables also give correct/accepted counts.
The final system localizes 54/57 accepted detections on `test` (94.74%) and 126/126 on `eval` (100%).

Timing is candidate-generation plus matcher-call time, not end-to-end runtime. It excludes image reads, crop
preparation, depth-feature computation, threshold decisions and model initialization, including in the no-matcher row.
DINOv2 source is pinned to revision `7764ea0f912e53c92e82eb78a2a1631e92725fc8`. Package versions are in `requirements.txt`.
